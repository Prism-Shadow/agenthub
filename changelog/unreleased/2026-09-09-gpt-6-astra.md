# Support GPT-6 Astra

- **Date:** 2026-09-09
- **Type:** feature
- **Scope:** `gpt6`, `registry`, `auto_client`, `openai_responses`
- **PR:** [#204](https://github.com/Prism-Shadow/agenthub/pull/204)

[中文版](2026-09-09-gpt-6-astra.zh.md)

## What changed

- AgentHub supports `gpt-6-astra` on the official OpenAI API and on OpenRouter as
  `openai/gpt-6-astra`: text and image in, text out, a 1,050,000-token context window,
  922,000 max input tokens and 128,000 max output tokens.
- The wire contract is identical to the GPT-5.6 generation, so the shared client folder is
  renamed for the newest generation as usual: `gpt5_6/` becomes `gpt6/` and `GPT5_6Client`
  becomes `GPT6Client` in both languages. Every official OpenAI registry row that named
  `gpt-5.6` as its client now names `gpt-6`.
- `auto_client.py` / `autoClient.ts` route `gpt-6` alongside `gpt-5.6`, `gpt-5.5` and
  `gpt-5.4`, and the unsupported-client-type message lists it. `gpt-5.6`, `gpt-5.5` and
  `gpt-5.4` remain accepted `client_type` spellings and reach the renamed client.
- `ThinkingLevel.NONE` degrades to `low` on a `gpt-6` model id. The generation rejects both
  `none` and `minimal` with HTTP 400 `Unsupported value: 'none' is not supported with the
  'gpt-6-astra' model. Supported values are: 'low', 'medium', 'high', 'xhigh', and 'max'.`
  Other model ids keep `none`. The generic `openai_responses` client applies the same rule,
  because the OpenRouter row for `openai/gpt-6-astra` routes through it.
- A reasoning item's `encrypted_content` is captured from `response.output_item.done` alone.
  The streaming-events reference says of `response.output_item.added`: "The output item that
  was added. For reasoning items, `encrypted_content` may be incomplete while the item is in
  progress. Use the reasoning item from the corresponding `response.output_item.done` event
  when passing it as input to a subsequent request." The client comment now cites that
  sentence, and a paired offline test pins the rule by streaming a truncated
  `encrypted_content` on the added event and asserting only the completed value reaches the
  replayed reasoning item.
- `gpt-6-astra` replaces `gpt-5.6-luna` in the env-gated E2E model lists, official and
  OpenRouter.
- `llmsdk_docs/gpt6/` snapshots the model page, the GPT-6 model guide, the reasoning guide and
  the prompt-caching guide; the `POST /v1/responses` reference snapshot is refreshed, and
  `llmsdk_docs/openai_responses/docs/openai-responses-streaming-events.md` adds a labelled
  excerpt of the streaming-events reference covering the output-item lifecycle events, the
  `response.reasoning_*` events, the terminal events and the usage object.

## Registry metadata

| Field | `gpt-6-astra` | `openai/gpt-6-astra` |
| --- | --- | --- |
| `base_url` | `https://api.openai.com/v1` | `https://openrouter.ai/api/v1` |
| `client` | `gpt-6` | `openai-responses` |
| Input / output modalities | Text, Image / Text | Text, Image / Text |
| `context_window` | 1,050,000 | 1,050,000 |
| `pricing` | `usd(12.5, 50.0, 1.0)` | `usd(12.5, 50.0, 1.0)` |

OpenAI's list price per 1M tokens is $1 cached input, $10 uncached input, $12.5 cache writes
and $50 output; above 272K input tokens the input and cache rates double and the output rate
is 1.5x, Batch and Flex are 50% of standard and Fast mode is 2x. The prompt bucket carries the
cache-write rate, because AgentHub's usage buckets do not separate cache-written input from
plain input. OpenRouter's models API reported the same four rates for the default OpenAI
endpoint on 2026-09-09, with no discount.
